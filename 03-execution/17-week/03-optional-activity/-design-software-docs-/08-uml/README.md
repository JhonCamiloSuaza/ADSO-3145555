# UML y diagramas

Esta carpeta concentra la arquitectura visual del proyecto. Los diagramas deben ayudar a entender una relacion, flujo o decision; no se crean por llenar espacio.

## Proposito

Apoyar la comunicacion del equipo cuando una tabla o texto no sea suficiente. Un buen diagrama debe aclarar el orden de modulos, dependencias, datos o flujos.

| Documento | Que explica | Estado |
|-----------|-------------|--------|
| [indice-diagramas.md](./indice-diagramas.md) | Diagramas sugeridos, tipo, proposito y estado | Definido |

## Diagramas recomendados

- Mapa de modulos funcionales.
- Flujo de promocion documental.
- Mapa de dependencias de servicios propuestos.
- Modelo conceptual de datos.
- Flujo de asignacion de horarios.
- Flujo de seguimiento de proyectos formativos.

## Regla

Todo diagrama debe tener fuente editable cuando se cree. Si no se puede modificar despues, no sirve como artefacto vivo de documentacion.
