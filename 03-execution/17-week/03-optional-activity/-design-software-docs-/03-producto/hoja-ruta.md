# Hoja de ruta

Esta hoja de ruta propone el orden para madurar la documentacion y preparar el proyecto para implementacion futura.

## Fase 1 - Base documental

Objetivo: que el repositorio sea entendible.

- Definir contexto y alcance.
- Organizar carpetas en espanol y con nombres claros.
- Documentar los 10 modulos funcionales.
- Eliminar archivos vacios o sin decision documental.
- Establecer reglas de gobernanza y trazabilidad.

## Fase 2 - Dominio y requisitos

Objetivo: conectar el negocio con necesidades documentables.

- Completar entidades y reglas por modulo.
- Definir eventos de dominio.
- Escribir requisitos funcionales y no funcionales.
- Completar historias de usuario.
- Mantener matriz de trazabilidad.

## Fase 3 - Arquitectura y datos

Objetivo: preparar decisiones tecnicas sin sobrecargar el proyecto.

- Documentar vista de arquitectura.
- Registrar ADR cuando exista una decision relevante.
- Definir modelo conceptual de datos.
- Definir diccionario de datos.
- Documentar estrategia de migracion conceptual.

## Fase 4 - APIs y microservicios propuestos

Objetivo: organizar limites tecnicos sin inventar implementaciones.

- Completar catalogo de servicios propuestos.
- Definir dependencias entre servicios.
- Documentar eventos candidatos.
- Definir contratos API cuando existan requisitos claros.
- Usar checklist antes de crear carpetas reales de servicios.

## Fase 5 - Manuales, calidad y operacion

Objetivo: preparar el repositorio para trabajo en equipo.

- Completar manual de usuario.
- Completar manual de administrador.
- Completar induccion tecnica.
- Mantener riesgos y KPIs documentales.
- Revisar calidad antes de promover ramas.

## Orden funcional recomendado

1. Seguridad y Acceso.
2. Estructura Institucional.
3. Parametrizacion.
4. Infraestructura.
5. Programas de Formacion.
6. Oferta y Programas.
7. Actores.
8. Horarios.
9. Proyectos Formativos.
10. Coordinacion y Eventos.
