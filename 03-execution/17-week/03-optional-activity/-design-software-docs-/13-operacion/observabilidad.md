# Observabilidad

Este documento define que deberia poder observarse cuando el sistema exista. Por ahora funciona como guia conceptual.

## Que observar

| Area | Ejemplo |
|------|---------|
| Acceso | Inicios de sesion, errores de permiso |
| Catalogos | Cambios en parametros base |
| Ambientes | Cambios de disponibilidad |
| Horarios | Asignaciones, conflictos e incidencias |
| Proyectos | Seguimientos, alertas y KPIs |
| Documentos | Generacion de evidencias o reportes |

## Regla

Toda observabilidad debe relacionarse con trazabilidad y auditoria. No se documentan herramientas reales hasta que arquitectura lo decida.
