# Experiencia de usuario

Esta carpeta describe como podria navegarse y entenderse el sistema desde la perspectiva de sus usuarios. No contiene pantallas finales; contiene criterios para que el diseno futuro respete el orden funcional del proyecto.

## Proposito

Conectar los modulos del dominio con una experiencia de uso coherente. Si el usuario debe trabajar con horarios, antes necesita poder entender programas, fichas, actores y ambientes.

## Que no va aqui

- Disenos finales sin validacion.
- Imagenes decorativas sin relacion funcional.
- Flujos que contradigan el dominio.

## Regla

La experiencia de usuario debe seguir la logica del negocio: bases institucionales, oferta academica, actores, horarios, seguimiento y coordinacion.
